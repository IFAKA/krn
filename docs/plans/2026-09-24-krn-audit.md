# KRn Architecture Audit and Simplification Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Leave KRn as a small, fail-open deterministic CLI whose persistent mechanisms directly avoid repeated useful work.

**Architecture:** Preserve repository reconstruction, bounded recoverable evidence, explicit irreducible state, authoritative verification, and explicit-input content-addressed execution reuse. Remove the review-only exact-command compiler because it does not execute, validate semantic equivalence, or reduce work; retain only the metrics needed by existing operational evidence and the cache benchmark.

**Tech Stack:** Go 1.24+, standard library, Git, ripgrep when available, project-native checks.

---

### Task 1: Establish the current baseline

**Files:** `main.go`, `eval.go`, `*_test.go`, `README.md`, `benchmark.sh`

1. Inspect command dispatch, storage, cache, verification, integration, evaluation, tests, and docs.
2. Run tests, vet, shell syntax, and the deterministic benchmark with a writable temporary `GOCACHE`.
3. Record only behavior that is directly established by source and checks.

### Task 2: Remove the non-operative compiler path

**Files:** `main.go`, `main_test.go`, `README.md`

1. Remove `compile` dispatch, candidate grouping, and its routing instruction.
2. Delete tests and documentation for exact-command review candidates.
3. Keep execution metrics only where they support observable command/cache evidence.

### Task 3: Correct state syntax and avoid unnecessary uncached work

**Files:** `main.go`, `main_test.go`

1. Make the documented `state set objective TEXT` and `state add FIELD TEXT` forms the parser contract.
2. Add focused tests for state writes and malformed state rejection.
3. Compute cache dependencies and fingerprints only when `--cache` is enabled; ordinary command execution should not require input declarations.

### Task 4: Make evidence failures explicit without widening the architecture

**Files:** `main.go`, `main_test.go`, `README.md`

1. Preserve fail-open behavior for unavailable search tooling while reporting an explicit unavailable status.
2. Keep bounded output and full-log recovery semantics unchanged.
3. Update only documentation that describes removed or changed behavior.

### Task 5: Verify the final system

1. Run focused tests, full tests, race tests, vet, build, shell syntax, and the cache benchmark with an isolated writable Go cache.
2. Run CLI smoke checks for state, context, verification, cache reuse, and integration idempotence/removal where practical.
3. Review the final diff for dead superseded code, generated drift, and documentation claims not backed by source.
